# OpenID Client

Creates and manages a Keycloak **OpenID Connect client** and everything attached to it:
access settings, OAuth2 capabilities, login/logout behavior, fine-grained authorization &
permissions, client scopes, the full set of protocol mappers, and client-scoped role
mappers. Wraps [`keycloak_openid_client`][client] (provider **5.8.0**) and its companion
resources ([`_protocol_mapper`][mapper], [`_default/optional_client_scopes`][scopes],
[`_client_permissions`][perms], [`_generic_role_mapper`][generic-rm] /
[`_ldap_role_mapper`][ldap-rm]).

[client]: https://registry.terraform.io/providers/keycloak/keycloak/latest/docs/resources/openid_client

## Shape: nested objects → flat provider args

Most inputs are grouped into **object variables** whose keys are camelCase mirrors of the
provider's arguments (`var.capabilities.standardFlowEnabled` → `standard_flow_enabled`).
Each key is `optional(…)`, so you only set what you need and unset keys leave the
provider's own defaults untouched. The collection inputs (`protocol_mappers`,
`role_mappers`, `permissions`) are **typed sets** where each element carries a `type` and a
matching sub-object — the same discriminated-union pattern the LDAP federation mappers use.

## Required inputs

`id`, `realm`, and `access_type` are the only required variables. `access_type` selects the
client kind and is validated:

- `CONFIDENTIAL` — server-side clients (Authorization Code / Client Credentials). Required
  for service accounts, authorization, and permissions.
- `PUBLIC` — browser-only clients with no secret (rely on redirect URIs).
- `BEARER-ONLY` — services that only accept bearer tokens, never initiate login.

The client secret is always generated by Keycloak and surfaced via the `client_secret`
output (sensitive); it is not a settable input.

## Variables

### General (top-level)

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | string | — (required) | The client ID. |
| `realm` | string | — (required) | Realm in which to create the client. |
| `access_type` | string | — (required) | `CONFIDENTIAL` \| `PUBLIC` \| `BEARER-ONLY`. |
| `name` | string | Title Case of `id` | Display name in the GUI. |
| `enabled` | bool | `true` | Whether the client is enabled. |
| `description` | string | `null` | Description shown in the GUI. |
| `always_display_in_console` | bool | `false` | List in the Account UI even without an active session. |
| `extra_config` | map(string) | `null` | Advanced OIDC settings passed through verbatim. |

### Grouped objects

| Variable | Maps to | Notable keys |
| --- | --- | --- |
| `access_settings` | Access settings | `rootUrl`, `adminUrl`, `baseUrl`, `redirectUris`, `postLogoutRedirectUris`, `webOrigins` |
| `capabilities` | Capability config | `standardFlowEnabled`, `implicitFlowEnabled`, `directAccessGrantsEnabled`, `serviceAccountsEnabled`, `standardTokenExchangeEnabled`, `oauth2DeviceAuthorizationGrantEnabled`, `pkceCodeChallengeMethod` (`plain`\|`S256`) |
| `login` | Login settings | `theme`, `consentRequired`, `displayOnConsentScreen`, `consentScreentText` |
| `logout` | Logout settings | `frontChannelLogoutEnabled`, `backchannelLogoutUrl`, `frontchannelLogoutUrl`, `backchannelLogoutSessionRequired`, `backchannelLogoutRevokeOfflineSessions` |
| `authorization` | Authorization (`null` ⇒ off) | `policyEnforcementMode`* (`ENFORCING`\|`PERMISSIVE`\|`DISABLED`), `decisionStrategy`, `allowRemoteResourceManagement`, `keepDefaults` |
| `scopes` | Client scopes | `default` (always included), `optional` (user can consent) |

\* required key when the group is supplied. `authorization` requires
`access_type = CONFIDENTIAL` and `capabilities.serviceAccountsEnabled = true`.

### Protocol mappers (`protocol_mappers`)

A `set` of objects, each with a `name`, a `type`, and a sub-object named after the `type`.
Supported types: `audience`, `audienceResolve`, `fullName`, `groupMembership`,
`hardcodedClaim`, `hardcodedRole`, `sub`, `userAttribute`, `userClientRole`,
`userProperty`, `userRealmRole`, `userSessionNote`. Most carry the usual
`addToIdToken` / `addToAccessToken` / `addToUserinfo` toggles. See
[`variables.tf`](variables.tf) for each sub-object's full key list.

### Permissions (`permissions`)

A `set` of fine-grained scope permissions for the client (Keycloak token-exchange preview
feature). Each element: `scope` (one of `view`, `manage`, `configure`, `map-roles`,
`map-roles-client-scope`, `map-roles-composite`, `token-exchange`), `policies`,
`decisionStrategy`, `description`. `null` (the default) leaves permissions unmanaged.

### Role mappers (`role_mappers`)

A `set` of role mappers attached to **this** client, each with a `type`:

- `generic` → [`keycloak_generic_role_mapper`][generic-rm]: adds an existing role
  (`generic.roleId`) to the client's scope mappings (use with `full_scope_allowed = false`).
- `ldap` → [`keycloak_ldap_role_mapper`][ldap-rm]: maps `cn=<role>` entries under an LDAP
  subtree into **client** roles of this client. `ldap.federationId` is the LDAP federation
  **name** (defaults to the realm name); the module resolves its GUID over the Admin REST
  API. This is what makes `var.creds` relevant (below).

  Each `ldap` mapper is then force-synced (`fedToKeycloak`) on every apply, because an
  `LDAP_ONLY` mapper otherwise materialises a client role only when a user who already
  holds it logs in — so a new role is never grantable. Import-only: a role deleted from
  LDAP is not removed from Keycloak.

### Admin credentials for LDAP role mappers (`creds`, sensitive)

Only used when a `role_mappers` element of type `ldap` is declared — the keycloak provider
has no data source to resolve a federation GUID by name, so the module mints an admin token
to query the Admin REST `components` endpoint. Under Crossplane it prefers the
provider-mounted credential files; `var.creds` (`url`, `client_id`, `username`, `password`)
is the fallback for standalone Terraform and tests. Inert otherwise.

## Outputs

| Name | Description |
| --- | --- |
| `id` | The client ID. |
| `name` | The client name. |
| `client_secret` | The generated client secret (sensitive). |
| `resource_server_id` | Resource-server ID when `authorization` is set, else `null`. |
| `service_account_user_id` | Service-account user ID when service accounts are enabled, else `null`. |
| `authorization_resource_server_id` | Authorization resource-server ID when `permissions` are set, else `null`. |

(see [`outputs.tf`](outputs.tf))

## Example

```hcl
module "client" {
  source = "git::https://github.com/kubed-io/terraform-keycloak-components.git//modules/openid-client?ref=main"

  realm       = "kubed"
  id          = "my-app"
  access_type = "CONFIDENTIAL"

  access_settings = {
    redirectUris = ["https://app.example.com/*"]
    webOrigins   = ["+"]
  }

  capabilities = {
    standardFlowEnabled     = true
    serviceAccountsEnabled  = true
    pkceCodeChallengeMethod = "S256"
  }

  protocol_mappers = [
    {
      name = "groups"
      type = "groupMembership"
      groupMembership = {
        claimName    = "groups"
        fullPath     = false
        addToIdToken = true
      }
    },
  ]
}
```
